01 // HISTORICAL ORIGIN

The Origin & Genesis of Pandas

How a quantitative crisis at AQR Capital Management led Wes McKinney to build the foundational pillar of modern data science.

The Quantitative Crisis (2008) GENESIS STORY

In 2008, Wes McKinney was working as a quantitative researcher at AQR Capital Management. His mission was to analyze high-frequency financial ticks and economic indicators.

  • The Friction: Switching between R/SAS (good for stats) and Java/C++ (fast for production) was creating massive technical debt.
  • The NumPy Limitation: NumPy matrices were homogeneous (all floats). Financial tables required dates, ticker strings, customer IDs, and prices side-by-side with automatic alignment.
Etymology: Portmanteau of "PANel DAta" (an econometrics term for multi-dimensional structured data over time) and "Python Data Analysis".
The Evolution Timeline 2008 → PRESENT

04 // UNDER THE HOOD

Memory Layout: BlockManager vs Apache Arrow

How Pandas stores heterogeneous data in RAM, and why the Pandas 2.0 Apache Arrow revolution slashes memory usage.

1. Classic BlockManager (NumPy 2D Blocks) PANDAS 1.X

Columns of identical dtypes are clustered together into single contiguous 2D NumPy arrays:

[Float64Block (2, N)]: Holds 'price', 'revenue' → Contiguous C-array
[Int64Block (2, N)]: Holds 'user_id', 'age' → Contiguous C-array
[ObjectBlock (2, N)]: Holds 'city', 'email' → Array of Python Object Pointers
Object Array Drawback: Storing text as Python objects consumes 40+ bytes per string and causes severe cache thrashing.
2. Modern PyArrow Engine (Arrow 2.0+) PANDAS 2.0+

Apache Arrow uses unified columnar memory with zero-copy string buffers and validity bitmasks:

[Arrow ChunkedArray]: Zero-overhead contiguous bytes buffer for strings
[Bitmap Validity Mask]: 1 bit per cell indicates null/valid (No NaN float casting)
[Copy-on-Write (CoW)]: Views share buffers until modified, preventing accidental copies!
Arrow Performance: Up to 70% memory reduction and 2x–10x faster string queries and CSV parsing.

05 // 1D DATA STRUCTURE

What is a Pandas Series?

A Series is the foundational 1-Dimensional building block of Pandas. A DataFrame is simply an orchestrated collection of Series sharing a common index!

The Tripartite Anatomy of a Series CORE DEFINITION

A pd.Series consists of three interconnected components:

  • 1. Data Buffer (.values): A contiguous 1D array of values (backed by NumPy or Apache Arrow).
  • 2. Index Labels (.index): An array of explicit axis labels (strings, integers, timestamps) enabling $O(1)$ dictionary-speed lookups and label alignment.
  • 3. Metadata (.dtype & .name): Strict datatype enforcement plus an optional identifier tag.
The Mathematical Equation:
Series = 1D NumPy Array (Data) + Hashable Labeled Index + Dtype Metadata

06 // CREATION PATTERNS

How to Create a Pandas Series

Pandas provides flexible constructors to instantiate a Series from lists, NumPy arrays, dictionaries, scalars, and missing values.

pd.Series(data=None, index=None, dtype=None, name=None, copy=False)
1. From Python List / Tuple LIST / TUPLE

Default index is a 0-indexed RangeIndex(0, N). Pass index=[...] for custom labels:

LIST CREATION
import pandas as pd # Default integer RangeIndex (0, 1, 2) s1 = pd.Series([10, 20, 30]) # With custom string labels & name s2 = pd.Series( [100, 200, 300], index=['q1', 'q2', 'q3'], name='sales' )
2. From NumPy ndarray NUMPY ARRAY

Wraps the existing NumPy memory buffer directly with zero overhead:

NUMPY CREATION
import numpy as np import pandas as pd arr = np.array([1.5, 2.8, 3.9, 4.2]) # Fast zero-copy Series creation s = pd.Series( arr, index=['a', 'b', 'c', 'd'], dtype='float32' )
3. From Python Dictionary DICT (KEYS → INDEX)

Dictionary keys automatically become the Series index; values become data items:

DICT CREATION
data_dict = {'AAPL': 182, 'GOOG': 140, 'MSFT': 415} # Automatic index from keys s = pd.Series(data_dict, name='prices') # If custom index passed, reindexes with NaN for missing keys: s_reindexed = pd.Series(data_dict, index=['AAPL', 'TSLA']) # TSLA → NaN
4. From Scalar (Broadcasting) BROADCAST SCALAR

Pass a single scalar and an index list → the scalar broadcasts across all labels:

SCALAR BROADCAST
# Broadcast scalar value 0.0 across 4 labels: zeros = pd.Series( 0.0, index=['epoch_1', 'epoch_2', 'epoch_3'], name='loss' ) # epoch_1 → 0.0 # epoch_2 → 0.0 # epoch_3 → 0.0
5. Specifying Explicit Dtypes DTYPES & ARROW

Downcast memory footprint for ML using categorized or PyArrow types:

DTYPE SPECIFICATION
# 1. Categorical (huge memory saver) s_cat = pd.Series(['S', 'M', 'L', 'S'], dtype='category') # 2. PyArrow string (zero-copy in Pandas 2.0+) s_arrow = pd.Series(['apple', 'banana'], dtype='string[pyarrow]')
6. Missing Values & Nullability NAN / NONE / PD.NA

How Pandas handles None, np.nan, and native pd.NA:

NULLABLE SERIES
import numpy as np # Classic NumPy promotion (integers cast to float64) s_classic = pd.Series([1, 2, np.nan, None]) # float64 # Pandas nullable integer (preserves int + pd.NA) s_nullable = pd.Series([1, 2, None], dtype='Int64')

            SERIES VS DATAFRAME

Removing & Dropping Columns

          

            Prune unneeded features, prevent data leakage, and drop temporary variables safely using df.drop(), del, pop(), and column comprehensions.
          

        

      


      

        
        

          

            1. Using df.drop() & Axis Orientation
            DF.DROP
          

          

            Specify columns=[...] or set axis=1 (Axis 0 = Rows, Axis 1 = Columns):
          


          

            
DROPPING COLUMNS

            
# Preferred Modern Syntax: Explicit columns parameter

13 // ROW INDEXING

          
Selecting Rows: .loc (Label) vs .iloc (Integer)

          

            Pandas provides two distinct indexers: .loc operates strictly on explicit human labels, while .iloc operates strictly on 0-indexed integer positions.
          

        

      


      

        
        

          

            1. Label-Based Row Selection (.loc)
            .LOC[LABEL]
          

          

            Uses explicit index strings/integers. Crucial rule: Slicing with .loc is INCLUSIVE of the end boundary!
          


          

            
LOC ROW SELECTION

            
# Select a single row → Returns 1D pd.Series
row_series = df.loc['emp_1']

# Select multiple specific rows → Returns 2D pd.DataFrame
rows_df = df.loc[['emp_1', 'emp_3']]

# Label Slicing: 'emp_1' through 'emp_3' (INCLUSIVE: emp_3 is INCLUDED!)
slice_df = df.loc['emp_1':'emp_3']

          

        


        
        

          

            2. Integer Position-Based Selection (.iloc)
            .ILOC[INT_POS]
          

          

            Uses standard 0-indexed integer offsets. Standard Python rule: Slicing with .iloc is EXCLUSIVE of the end boundary!
          


          

            
ILOC ROW SELECTION

            
# Select first row (pos 0) → Returns 1D pd.Series
first_row = df.iloc[0]

# Select last row (pos -1)
last_row = df.iloc[-1]

# Multiple rows by position
sample_rows = df.iloc[[0, 2]]

# Positional Slicing: 0 to 3 (EXCLUSIVE: items 0, 1, 2 only; 3 excluded!)
slice_iloc = df.iloc[0:3]

          

        

      


      
      

        

          
            

              Feature
              df.loc[start:stop]
              df.iloc[start:stop]
            

          
          
            

              Addressing Scheme
              Explicit index labels (e.g. '2026-01-01', 'emp_1')
              Integer positions (0, 1, 2, ..., N-1)
            

            

              Endpoint Inclusion
              INCLUSIVE (The stop label is included)
              EXCLUSIVE (The stop index is excluded)
            

            

              Negative Indices
              Raises KeyError unless -1 is an explicit string label
              Supported (e.g. df.iloc[-1] selects last row)

14 // 2D SUBSETTING

          
Selecting Subsets of Rows & Columns (2D Slicing)

          

            Slice both dimensions simultaneously using [row_indexer, column_indexer]. Leverage ultra-fast scalar accessors .at and .iat, and prevent the dreaded SettingWithCopyWarning.
          

        

      


      

        
        

          

            1. Simultaneous 2D Slicing (loc & iloc)
            [ROWS, COLS]
          

          

            The canonical syntax is indexer[row_selection, col_selection]:
          


          

            
2D MATRIX SUBSETTING

            
# 1. 2D Label Slicing: rows 'emp_1' to 'emp_3', cols 'Name' & 'Salary'

# 3. 2D Positional Slicing: first 3 rows, first 2 columns
sub3 = df.iloc[0:3, 0:2]

# 4. All rows, specific columns by position:
features = df.iloc[:, 1:4]

          

        


        
        

          

            2. Fast Scalars (.at / .iat) & SettingWithCopy
            PERFORMANCE & SAFETY
          


          

            
FAST SCALARS & SAFE MUTATION

val_label = df.at['emp_1', 'Salary']   # 98000.0
val_pos   = df.iat[0, 3]              # 98000.0

# Modify single cell at lightning speed:
df.at['emp_1', 'Salary'] = 102000.0

# ❌ WRONG: Chained indexing causes SettingWithCopyWarning:
# df[df['Dept'] == 'ML']['Salary'] = 130000.0

# ✅ RIGHT: Single atomic .loc call sets values safely:

15 // BOOLEAN FILTERING

          
Conditional Selection & Compound Boolean Masks

          

            Filter rows dynamically based on business logic. Learn bitwise logic (&, |, ~), set membership (.isin), numerical ranges (.between), string patterns, and SQL-like .query().
          

        

      


      

        
        

          

            1. Bitwise Operators: & (AND), | (OR), ~ (NOT)
            COMPOUND MASKS
          

          

            In Pandas, you must use bitwise operators (&, |, ~) and wrap every condition in parentheses (...):
          


          

            
BOOLEAN FILTERING SYNTAX

            
# 1. Single condition: Employees earning >= 100,000
high_earners = df[df['Salary'] >= 100000]

# 2. Compound AND (&): ML dept AND Age < 35
young_ml = df[(df['Dept'] == 'ML') & (df['Age'] < 35)]

# 3. Compound OR (|): Data dept OR Salary >= 120000
special_tier = df[(df['Dept'] == 'Data') | (df['Salary'] >= 120000)]

# 4. Inverted NOT (~): Exclude 'Eng' department
non_eng = df[~(df['Dept'] == 'Eng')]

          


          

            Why and / or Break: Python's native and/or evaluate truthiness of entire array objects, raising ValueError: The truth value of a Series is ambiguous. Bitwise &/| evaluate element-wise.
          

        


        
        

          

            2. .isin(), .between(), Text Filters & .query()
            ADVANCED QUERYING
          


          

            
ADVANCED FILTERING METHODS

            
# 1. Set Membership with .isin([...])
tech_roles = df[df['Dept'].isin(['ML', 'Data', 'AI'])]

# 2. Numeric Range with .between(low, high) (Inclusive)
mid_range = df[df['Salary'].between(80000, 110000)]

# 3. String Regex / Prefix filtering:
a_names = df[df['Name'].str.startswith('A')]

# 4. Expressive SQL-like .query() method:
min_sal = 90000
query_res = df.query("Dept == 'ML' and Salary >= @min_sal")

          


          

            The @variable Syntax in .query(): The @ prefix lets you reference local Python variables directly inside your query string, making dynamic UI dashboards incredibly clean!

23 // KNOWLEDGE CHECK

          
Series & DataFrame Flashcards

          

            Test your core mastery of Pandas Series, DataFrames, indexing mechanics, and vector filters.
          

        

      


      

        
        

          
1. What is the difference between df['Salary'] and df[['Salary']]?

          
          

            df['Salary'] (single bracket) returns a 1D pd.Series of shape (N,). In contrast, df[['Salary']] (double brackets) returns a 2D pd.DataFrame containing a single column of shape (N, 1).
          

        


        
        

          
2. Why does loc['a':'c'] include 'c', while iloc[0:3] excludes position 3?

          
          

            .loc uses explicit human labels where users expect both endpoints to be inclusive (e.g. date ranges 'Jan':'Mar' should include March). .iloc uses 0-indexed integer offsets following Python's standard half-open slice convention [start, stop) where stop is exclusive.
          

        


        
        

          
3. Why must you use & and | instead of 'and' / 'or' when filtering DataFrames?

          
          

            Python's native and/or operators short-circuit and evaluate the single boolean truth value of entire objects, raising a ValueError on arrays. Bitwise operators (&, |, ~) evaluate conditions element-by-element across every row, producing a full boolean mask Series.
          

        


        
        

          
4. Why are df.at and df.iat faster than df.loc and df.iloc for single cells?

          
          

            .loc and .iloc contain heavy overhead to support series slicing, dimension checking, and data alignment. .at and .iat bypass this overhead and access the raw memory buffer directly for $O(1)$ scalar lookup and mutation.
